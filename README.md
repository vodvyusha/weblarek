# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

#### Интерфейсы данных
В проекте реализованы две сущности для хранения данных - товар и покупатель.

Товар:
```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

Интерфейс IProduct описывает структуру данных товара. Он используется для хранения информации о товаре, отображаемой в каталоге и корзине.

Покупатель:
```ts
interface IBuyer {
  payment: TPayment | null;
  email: string;
  phone: string;
  address: string;
}
```

Интерфейс IBuyer описывает данные покупателя, необходимые для оформления заказа.

#### Модели данных

#### Класс ProductCatalog
Класс отвечает за хранение списка товаров и деталей выбранного для подробного просмотра товара.

`constructor(events: IEvents)` – принимает брокер событий.

Защищенные поля класса:  
`products: IProduct[]` - массив всех товаров, полученных с сервера. 
`preview: IProduct | null` - товар, выбранный для подробного отображения. Если товар не выбран, содержит `null`.

Методы класса:  
`setProducts(products: IProduct[]): void` - принимает массив товаров и сохраняет его в модели.
`getProducts(): IProduct[]` - возвращает массив всех товаров, хранящихся в модели.
`getProduct(id: string): IProduct | undefined` - принимает id товара и возвращает соответствующий товар из каталога. Если товар не найден, возвращает `undefined`.
`setPreview(product: IProduct): void` - принимает товар и сохраняет его как выбранный для подробного отображения.
`getPreview(): IProduct | null` - возвращает выбранный для подробного отображения товар. Если товар не выбран, возвращает `null`.

#### Класс Cart
Класс отвечает за хранение и управление товарами, выбранными покупателем для оформления заказа.

Конструктор:
`constructor(events: IEvents)` – принимает брокер событий.

Поля класса:
`items: IProduct[]` - массив товаров, добавленных покупателем в корзину.

Методы класса:  
`getItems(): IProduct[]` - возвращает массив товаров, находящихся в корзине.
`addProduct(product: IProduct): void` - принимает товар и добавляет его в корзину.
`removeProduct(product: IProduct): void` - принимает товар и удаляет его из корзины.
`clear(): void` - удаляет все товары из корзины.
`getTotal(): number` - вычисляет и возвращает общую стоимость всех товаров, находящихся в корзине.
`getCount(): number` - возвращает количество товаров, находящихся в корзине.
`hasProduct(id: string): boolean` - принимает идентификатор товара и возвращает `true`, если товар уже находится в корзине, иначе возвращает `false`.

#### Класс Buyer
Отвечает за хранение и управление данными покупателя, необходимыми для оформления заказа.

`constructor(events: IEvents)` – принимает брокер событий.

Поля класса:
`payment: TPayment` - хранит выбранный способ оплаты.  
`address: string` - хранит адрес доставки.  
`phone: string` - хранит номер телефона покупателя.  
`email: string` - хранит адрес электронной почты покупателя.

Методы класса:
`setData(data: Partial<IBuyer>): void` - принимает объект с данными покупателя и сохраняет переданные значения в модели, не изменяя остальные уже сохраненные данные.
`getData(): IBuyer` - возвращает все данные покупателя.
`clear(): void` - очищает все данные покупателя.
`validate(): Partial<Record<keyof IBuyer, string>>` - выполняет проверку заполненности данных покупателя и возвращает объект с ошибками валидации. Если поле заполнено корректно, соответствующее свойство в объекте отсутствует.

#### Слой коммуникации
Отвечает за взаимодействие приложения с сервером. Его задача заключается в получении данных с сервера и отправке данных заказа.

#### Класс WebLarekApi
Отвечает за взаимодействие с сервером приложения. Получает с сервера список товаров и отправляет данные оформленного заказа.

Конструктор:
`constructor(private api: IApi)` – принимает объект, реализующий интерфейс IApi, который используется для выполнения запросов к серверу.

Методы класса:
`getProducts(): Promise<IProductsResponse>` – выполняет GET-запрос на эндпоинт /product/ и возвращает промис с объектом, содержащим общее количество товаров и массив товаров каталога.
`createOrder(order: IOrder): Promise<IOrderResult>` – принимает объект заказа, выполняет POST-запрос на эндпоинт /order/ и возвращает промис с объектом, содержащим идентификатор оформленного заказа и его итоговую стоимость.

#### Слой представления (View)
Слой представления отвечает за отображение интерфейса интернет-магазина и обработку действий пользователя. Он содержит компоненты, которые работают с DOM-элементами: отображают данные, изменяют состояние элементов интерфейса и генерируют события при взаимодействии пользователя с приложением.

Компоненты View не содержат бизнес-логику и не взаимодействуют напрямую с моделями данных или API. Для передачи пользовательских действий они используют брокер событий, а полученные от Presenter данные отображают через свойства и методы компонентов.

`constructor(events: IEvents, container: HTMLElement)` - принимает брокер событий для генерации событий пользовательских действий и ссылку на корневой DOM-элемент шапки магазина.

Поля класса:
`basketCounter: HTMLElement` - элемент, отображающий количество товаров в корзине.

Методы класса:

#### Класс Gallery

Методы класса:

Отвечает за отображение корзины товаров. Отображает список добавленных товаров, их общую стоимость и кнопку перехода к оформлению заказа.

#### Класс Success
Отвечает за отображение сообщения об успешном оформлении заказа.

Конструктор:
`constructor(events: IEvents, container: HTMLElement)` – принимает брокер событий и контейнер с разметкой компонента.

Поля класса:
`descriptionElement: HTMLElement` – элемент, отображающий информацию о списанной сумме.
`closeButton: HTMLButtonElement` – кнопка перехода к дальнейшим покупкам.

Методы класса:
`set total(value: number)` – отображает сумму, списанную за заказ.

## События приложения
В разделе представлены события, генерируемые компонентами приложения в ответ на действия пользователя. В приложении используется брокер событий EventEmitter. События позволяют разделить слой представления (View), модели данных (Model) и Presenter.

### События слоя представления (View)

#### Header
`basket:open` - генерируется при нажатии на кнопку корзины.

#### Basket
`basket:order` – генерируется при нажатии на кнопку «Оформить» в корзине.
`basket:item-delete'` - генерируется обработчиком удаления при нажатии на кнопку удаления товара в BasketCard. В событии передаётся удаляемый товар.

#### CatalogCard
`card:select` – генерируется при выборе товара в каталоге.

#### PreviewCard
`card:add-to-basket` - генерируется при нажатии на кнопку добавления товара в корзину. В текущей реализации добавление товара выполняется через callback onClick, переданный в конструктор PreviewCard.

#### BasketCard
`basket:item-delete` – генерируется при нажатии на кнопку удаления товара из корзины. Сам BasketCard получает callback onDelete через конструктор. Callback передаётся из Presenter и внутри него генерируется событие basket:item-delete.

#### Form
`form:submit` - генерируется при отправке формы.

#### OrderForm
`payment:change` - генерируется при выборе способа оплаты.
`order:change` - генерируется при при изменении значения поля адреса.

#### ContactsForm
`contacts:change` - генерируется при изменении поля email или телефона.

#### Success
`order-success:close` - генерируется при нажатии на кнопку «За новыми покупками!».

#### Modal
`modal:close` - генерируется при нажатии на кнопку закрытия модального окна или при клике вне области его содержимого.

### События модели данных (Model)

#### ProductCatalog
`catalog:change` - генерируется при изменении списка товаров в каталоге.
`preview:change` - генерируется при изменении товара, выбранного для предпросмотра.

#### Cart
`cart:change` - генерируется при изменении содержимого корзины. Событие возникает при добавлении, удалении товара или очистке корзины.

#### Buyer
`buyer:change` - генерируется при изменении данных покупателя. Событие возникает после изменения способа оплаты, адреса, email или телефона, а также после очистки данных покупателя.

### События Presenter
Presenter не является самостоятельным источником пользовательских событий. Он подписывается на события View и Model, обрабатывает их и при необходимости инициирует другие события.

`card:select` - получает выбранный товар от CatalogCard и передаёт его в ProductCatalog:
```ts
events.on('card:select', ({ product }) => {
  productsModel.setPreview(product);
});
```

`basket:item-delete` - получает товар от BasketCard и передаёт его в Cart для удаления:
```ts
events.on('basket:item-delete', ({ product }) => {
  cartModel.removeProduct(product);
});
```

`payment:change` - получает выбранный способ оплаты от OrderForm и обновляет данные покупателя:
```ts
events.on('payment:change', ({ payment }) => { 
  buyerModel.setData({ payment });
});
```

`order:change` - получает изменение адреса от OrderForm и обновляет данные покупателя:
```ts
events.on('order:change', ({ field, value }) => { 
  buyerModel.setData({
    [field]: value,
  });
});
```

`contacts:change` - получает изменения email или телефона от ContactsForm и обновляет данные покупателя:
```ts
events.on('contacts:change', ({ field, value }) => {
  buyerModel.setData({
    [field]: value,
  });
});
```

`form:submit` - обрабатывает отправку обеих форм. 
Для order выполняется проверка оплаты и адреса. Если данные корректны, открывается ContactsForm.
Для contacts выполняется полная валидация данных покупателя. Если данные корректны, Presenter формирует заказ и отправляет его через API.

`order-success:close` - закрывает модальное окно после успешного оформления заказа:
```ts
events.on('order-success:close', () => {
  modal.close();
});
```

`modal:close` - закрывает модальное окно при нажатии на кнопку закрытия:
```ts
events.on('modal:close', () => {
  modal.close();
});
```
